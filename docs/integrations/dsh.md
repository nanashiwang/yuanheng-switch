# DSH 一键配置

从工具管理或顶部应用选择器选择 **DSH**，选择元亨分组和模型，再点击配置。元亨同步该分组的文本模型目录，按 Chat Completions、Responses、Messages 协议分别创建供应商，并设置新会话的默认模型。

## 桌面端与本机 Web

默认写入 `~/.dsh/profiles/desktop/cordis.patch.yml` 和 `~/.dsh/profiles/web/cordis.patch.yml`。如果启动元亨的环境指定了绝对路径 `DSH_HOME`，则使用该目录。两个 profile 共用 `.credentials.yaml` 内的 `YUANHENG_DSH_API_KEY`，配置文件只保存凭据引用。

- 安装版桌面端：自动检测 DeepSeek Harness，或手动选择应用路径。
- 源码版：选择已经安装依赖并构建完成的 `deepseek-harness` 根目录；启动通过该目录运行 `pnpm run start:desktop`。
- 本机 Web：点击 **启动 DSH Web** 会先应用当前选择，再运行 `pnpm dsh --profile web`；未选择源码目录时使用 PATH 中的 `dsh --profile web`。由 DSH 自己打开带认证信息的网页。
- 未安装桌面端也可以配置本机 Web。自定义 profile、其他用户的数据目录和远程 Web 不在自动配置范围内。

模型切换对新会话生效；已有会话保留自身选择。已打开的 DSH 如未更新模型目录，请重新加载。首版仅声明文本输入，不推测图片支持、上下文长度或推理档位；这些能力后续可以在确认网关和模型能力后扩展。

## 配置保护与恢复

使用 DSH 的同名跨进程写入锁和原子替换。保留已有供应商、无关配置与凭据，只替换标记为元亨管理的区块。配置记录仅保存路径、模型信息及区块摘要，不复制 API Key 到元亨配置记录中。Unix 凭据文件及临时文件仅当前用户可读写。

全局模型覆盖、自定义凭据存储、同名供应商冲突或托管区块被外部修改时，停止写入并提示。DSH 自己的配置编辑器重新整理 YAML 后也可能触发该保护；此时应核对文件，不能直接覆盖用户修改。恢复工具配置会移除仍可验证归属的元亨区块，保留其他内容；恢复过程中发现外部修改则保留文件与凭据。

“已配置”表示本地配置保存并通过一致性检查；连接检查复用元亨现有账号、分组及凭据验证，不代表所有模型已经完成真实推理请求。

## 验证记录

本轮以 DSH `0.2.0-rc.1` 本地源码和隔离 DSH_HOME 验证：生成配置被 DSH 加载器接受；三种协议供应商通过 SDK 运行时初始化及本地模拟 SSE 服务，验证实际请求路径、凭据引用及回复。Messages 使用站点根地址，Chat/Responses 使用 `/v1` 根地址，避免 SDK 重复追加版本路径。未使用真实用户 Key 进行推理验收。
