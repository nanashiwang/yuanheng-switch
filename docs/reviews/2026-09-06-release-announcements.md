# 客户端内最近两版公告：对抗性审查

## 不变量

- 工作台、「关于 → 更新日志」和更新弹窗使用同一个内部阅读窗口，不依赖浏览器跳转。
- 客户端更新只保留最近两版；发布源、服务端输入标准化、显示列表与本地缓存均有限制。
- 平台通知保持独立，不把平台通知误当作版本公告裁剪。
- 公告请求仅匿名读取固定平台域名，不带账号、API 密钥、个人目录或设备标识；不接受任意 URL，不跟随重定向。
- 公告同步超时、错误、存储不可用均不得阻止工作台显示或工具使用。
- 公告只作文本渲染，不能执行脚本、加载远程图片或触发链接。
- 发布清单中的下载地址、签名、平台标识保持不变；只同步两版公告及本版正文。

## 反例与覆盖

| 反例 | 防护 |
| --- | --- |
| 服务端返回三版以上、重复版本或错误顺序 | 数值版本排序、去重、裁剪为两版 |
| 已经是最新版，更新器返回无更新 | 公告独立读取，不依赖更新器是否发现新版本 |
| 旧清单只有通用提示，没有两版公告字段 | 保留安装包自带或本地已保存的两版内容 |
| 网络错误、旧镜像回退 | 保持本地公告，不清空、不降级 |
| 新版本刚发布、本地缓存还未过期 | 用户打开窗口或切换到更新分类时主动刷新，不阻塞已有内容阅读 |
| 缓存损坏、过大、含旧版本 | 校验并重写为有限数据，不累加历史 |
| LocalStorage 禁用或已满 | 捕获读写错误，仍可查看正文和关闭提示 |
| 公告含 HTML、脚本、追踪图片或链接 | 作为 React 文本显示，无 HTML 注入和外部链接 |
| 发布版本号已改但忘记写公告 | 发布校验失败，不再次发布只有通用说明的清单 |
| 更新过程中打开公告 | 不改变更新状态、忽略版本或推迟提醒设置 |
| 长公告读到末尾后切换版本 | 新版本正文回到顶部，窗口关闭按钮保持可见 |
| 公告响应超大或持续不结束 | 后端总超时 8 秒、最大 128 KiB，逐块计数，不跟随重定向 |
