# 元衡全模型报价同步与闪电估算

## 本次已实现

- 客户端独立同步完整平台价格目录、账号有效分组倍率和显示单位；缓存按账号隔离，默认 6 小时有效，支持手动刷新，失败保留最近成功结果。
- 登录状态变化使报价查询失效，启动和用量页挂载时按缓存有效期同步。价格同步失败不阻塞模型调用。
- 使用受限表达式解释器，支持当前全部 10 条动态 Token 计价规则，包括长上下文阈值、上海时区工作日峰谷。普通 Token 模型按平台倍率计价，缓存输入遵循各协议语义。
- 首页、汇总、趋势、供应商/模型统计及请求详情统一显示闪电估算。API 汇总 `totalCost` 现在是平台参考额度，并带 `costSymbol`、`pricedRequests`、`unpricedRequests`；数据库原有 `*_cost_usd` 保持美元语义。
- 默认以每个模型最低可用报价作参考，可显式选择分组；这不是对历史实际路由的判断。官方账号与来源未确认的会话只折算使用价值，不认定为平台扣费。
- 历史逐请求记录按当前完整规则和请求时间重新估算；已经裁剪为日汇总的记录缺少上下文长度，列为未计入。未知模型、未知规则、缺少数量分别提示，不显示为免费。
- 按次/按时长模型进入目录并展示单价，但请求缺少实际计费数量/音频时长时不估算。平台账单对账、请求时价格快照、缺价即时触发同步尚未接入。

### 已核实的计算契约

通过平台当前公开前端 `utils-Dlw5d9LO.js`、`render-iRYXf8xe.js`、`quota-DoX3dhir.js` 核实：普通 Token 输入基价为 `model_ratio × 2 / 百万 Token`；表达式系数按百万 Token 计价；最终参考额度乘分组倍率和 `custom_currency_exchange_rate`。额度账单显示为 `quota / quota_per_unit × custom_currency_exchange_rate`。按时长报价单位为小时。

表达式中的 `p/c/cr/cc/len` 分别对应新鲜输入、输出、缓存读取、缓存写入、完整输入上下文；OpenAI 风格在表达式没有独立缓存项时保留对应输入。暂不支持的时区、请求参数、额外时间倍率规则不猜算，提示查看平台账单。

测试使用 2026-09-11 的公开 64 模型快照；快照不含登录凭证或用户消费记录。本次没有改动生产定价、用户余额或实际账单。本功能随客户端 v0.1.52 发布。

验证：前端 772 项测试通过；平台报价与表达式 6 项、用量统计 31 项、Token 计价/解析/日志 43 项、响应处理 13 项测试通过；TypeScript 检查、Clippy（禁止警告）及前端构建通过。

以下是后续完整结算能力的设计，不能视为本次已完成范围。

## 实施前现状

2026-09-11 读取元衡公开接口：

- [定价目录](https://cn.meta-api.vip/api/pricing) 返回 64 个模型：48 个普通 Token 计价、10 个表达式计价、5 个按次计价、1 个按时长计价。
- 表达式模型包含 GPT-6 Astra 的上下文阶梯，以及 DeepSeek 的工作日峰谷规则。不能仅提取 `model_ratio` 或四项 Token 单价；例如部分模型的缓存能力字段与表达式中的缓存项并非同一口径。
- 目录包含 `group_ratio`、`enable_groups`、`usable_group`、`auto_groups`、`billing_mode`、`billing_expr`。仅一个模型带 `pricing_version`，价格版本契约还不完整。
- [平台状态](https://cn.meta-api.vip/api/status) 返回 `quota_display_type=CUSTOM`、`custom_currency_symbol=⚡️`、`payment_currency_symbol=¥`、`quota_per_unit=500000`。平台额度、充值货币、官方 API 的 USD 参考价格不能混用。
- 客户端 `sync_connection` 已请求定价目录，但只通过 `collect_model_names` 提取名称；未保存价格或计费规则。
- 旧 `model_pricing` 表只有模型 ID 和四项固定美元单价，没有平台、账号、分组、计费单位或版本维度。把元衡报价直接覆盖进去，会串用其他供应商价格。

## 推荐的数据与显示口径

1. 元衡请求：使用当时适用的元衡分组规则预估，取得平台账单后显示已结算额度。
2. 官方账号：保持账号计费；可按用户选择的元衡参考分组折算使用价值，明确标注“元衡报价参考”，不记成元衡实际消费。
3. 其他 API / 来源未确认的会话：保留明确来源的参考价格，不按当前登录状态推断历史供应商。
4. 内置厂商价与 models.dev 导入保留为参考兜底。手工参考价独立保存，不覆盖平台实际结算金额，也不被自动同步抹掉。
5. 金额按单位和性质区分汇总。平台额度与 USD 不直接相加，预估与已结算也不作为同一笔费用重复统计。

## 同步流程

- 登录成功、手动刷新账号时同步；增加独立“同步价格”按钮。
- 定价缓存过期时在后台更新，例如默认 6 小时。遇到新模型缺价时合并触发一次刷新，不阻塞模型请求、不逐条反复请求。
- 只更新同步拥有的数据；失败保留上次成功快照，并显示最后成功时间和过期状态。
- 公共价格目录与账号有效分组规则分开缓存，按平台地址、账号隔离。切换账号后不能复用另一账号的优惠。
- 工具可用模型仍以账号模型接口及权限为准，不能把公共价格目录当作全部可调用模型。
- 下架模型从可选列表标记不可用，但不删除历史价格快照。
- 同步结束后刷新价格列表、缺价状态及相关用量视图；账号同步成功与价格同步成功分别展示。

## 服务端与客户端分工

服务端应由实际计费逻辑统一生成报价数据，复用或扩展现有接口，明确：

- 稳定模型 ID、计费模型/别名关系、账号生效分组及倍率优先级；自动分组请求的最终分组。
- 额度单位、币种/显示符号、换算基准；基础价格与已含倍率的最终价格不能重复乘倍率。
- Token、请求次数、音频时长等计价数量及单位。接口耗时不是音频计费时长。
- 上下文阶梯、峰谷时段、时区、适用时刻和舍入方式。
- 价格版本与有效期；版本变化应覆盖模型规则和分组倍率变化。
- 可关联请求的稳定 ID，以及完成后读取实际扣费结果的能力。

客户端保存原始快照和标准化规则，用统一计算器处理支持的规则，不继续逐模型写条件。表达式应由服务端转为约定的声明式规则，或复用一致的受限规则规范；不执行任意远程代码。

无法可靠解释的复杂规则、缺失的计价数量或单位，保持待定并以平台结算为准。不能退回某个看似相近模型的单价，也不能把缺失数据当免费。

## 请求记录与历史

每次真实请求保存实际供应商、账号范围、计费模型、分组、价格快照版本、时间及平台请求 ID。价格在请求中途刷新或用户切换分组，不应改变这次记录的计价依据。

费用状态需要显式区分：未定价、预估、待结算、已结算；Token 是否可用是另一项状态。按次模型即使没有 Token，仍可有已知费用。

账单对账只针对实际经过元衡的请求，按稳定请求 ID 批量关联。不要用“模型名 + 接近的时间”猜配，也不需要上传官方 ChatGPT 会话内容。

已有费用保留；缺价历史优先用当时快照补算。缺少历史分组或版本时，按当前价补算只能标为参考估算，不能声称恢复了当时实际扣费。

## 建议落地顺序

1. 接通全量目录、有效分组、单位与版本缓存，以及同步状态界面。
2. 对齐平台规则契约，接入统一预估计算和请求价格快照；把现有单模型规则降为独立参考兜底。
3. 对接平台实际扣费记录，将预估金额校准为已结算额度。

落地前需查看后端实现或确认接口契约，尤其是表达式变量单位、时长单位、倍率优先级、计价时间与舍入、请求 ID 和账单关联方式。当前公开响应本身不足以证明这些计算细节。

## 验收重点

- 平台新增模型、调整价格后无需发客户端版即可同步。
- 不同账号和分组不串价，不覆盖手工参考价。
- 阶梯边界、峰谷时段、缓存、按次和按时长费用与平台一致。
- 调价不改变已经结算的旧账，缺价不显示成零费用。
- 同步失败不清空缓存、不阻塞调用；未知规则明确提示。
- 官方请求和会话导入不被误记成元衡实际消费。
