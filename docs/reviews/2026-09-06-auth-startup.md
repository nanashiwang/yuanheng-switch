# 分组凭据与 Windows 启动修复审查

## 不变量

- 登录会话从系统凭据库读取；迁移清空 SQLite 后不得回到旧位置查询。
- 不以主令牌有效推断工具令牌有效；按工具入口及分组验证实际使用的凭据。
- 配置时从已登录账号重新获取目标分组 key，验证模型访问权限后才修改工具。
- 分组名不是特例；默认、auto、中文、自定义分组使用同一流程。
- 读取模型目录不等于成功生成；未观察到调用时不得显示完成或无限等待动画。
- Windows 旧核心退出前不覆盖二进制；更新失败保留可恢复的旧版本。
- 启动性能优化不关闭认证验证；缓存用于展示，启动/配置前仍检查目标工具。

## 对抗性检查

| 反例 | 防护 / 回归覆盖 |
| --- | --- |
| 安全存储中有会话、SQLite 没有会话 | 预检通过统一凭据读取入口，测试迁移后旧记录为空 |
| 主令牌正常，Desktop 令牌返回 401 | 独立验证 Desktop，要求重新配置，不误报账号失效 |
| CLI 与 Desktop 使用不同分组 | 不从另一个入口取 key；批量配置只按分组复用 |
| 5 类分组与 10 个工具组合 | 本地模拟目录/鉴权服务覆盖 50 个组合 |
| 502、429、超时 | 不据此删除会话、撤销 key 或认定令牌失效 |
| 新 key 尚未通过验证 | 不写入配置，不以后台生成代替鉴权探测 |
| 配置途中失败 | Codex 两份供应商、当前选择及文件恢复；旧目录引用保留 |
| 用户在网络校验期间退出或换账号 | 写入前复核登录会话，变化时停止本批写入 |
| “修复工具”覆盖原有分组 | 缺省参数保留各工具原模型、分组、推理等级 |
| 官方模式下误触元衡修复/启动 | 批量修复排除官方 Codex；启动不偷偷写回中转 |
| 重建凭据时先撤销旧 key | 保留旧 key，避免尚未重配的工具或其他设备中断 |
| Windows 文件被占用 | 临时文件准备后替换；锁定时不截断旧二进制；句柄释放后切换 |
| 缺少配置时间的旧安装遇到 401 | 允许展示近期失败；不以旧成功证明当前配置生效 |
| 会话导入记录伪装成代理请求 | 生效查询只读取真实 proxy 来源，不做账单回填写入 |
| 缓存过期、损坏、时间来自未来 | 过期可展示并后台更新；结构损坏或时间异常拒绝缓存 |
| 无请求记录、卡片紧凑布局 | 静态等待提示；失败代码和说明不隐藏、不无限转圈 |

## 验证边界

自动测试使用临时目录、内存数据库及模拟鉴权服务，不读取个人凭据、不请求真实生成。
Windows 文件占用测试由 Windows CI 执行；macOS 本地测试不能替代 Windows 实机验收。
代码合并不代表现有安装包已经更新；需后续新版本安装包发布后，原 Windows 设备再验证。
令牌保留策略需告知用户：不再自动撤销旧 key，需要撤销时由平台令牌管理明确操作。
网络体检改为按需执行；库存缓存是展示快照，重新检测按钮和目标工具启动校验仍保留。
