# 诊断快照与本机检测共享：第一性原理与对抗性审查

## 目标与不变量

1. 快不等于跳过验证。持久化的只有本机工具展示快照；账号、凭据与当前配置就绪状态不从库存快照恢复。
2. 同一轮本机探测由工作台和工具管理共享。远程 npm/GitHub/PyPI 版本查询不进入这两个页面的首屏路径。
3. 并发调用同一探测可以合并，但用户安装、改路径、重新检测后必须得到新结果。已结束的探测不在 API 层继续缓存。
4. 报告必须可用于排查，也必须最小化信息：只读取请求元数据列，不读取提示词、请求头、原始错误正文、账号名称或费用；路径只保留类别，分组使用报告内别名。
5. 预览、复制、导出是一份不可变快照。导出不能再次访问网络、更不能以旧的健康结论代表新检查结果。
6. 有模型目录访问权限不代表生成完成；HTTP 200 加流式错误也不能当作成功。

## 实现与边界

- 工作台和工具管理共用一个 Query 键、本地快照和仅本机的探测入口。API 层只合并正在进行的相同请求；后端对相同工具/路径/WSL 参数/检测代次合并探测，所有本机探测全局最多三个并发，阻塞探测不运行在异步执行线程。
- 改配置/重新检测提升检测代次，旧请求完成后不能重写新快照。登录相关工具状态、调用状态和诊断使用账号及同步时间隔离的查询键。
- 旧快照仅用于展示；刷新失败显示说明，启动/配置仍走已有预检和实际路径解析。没有新增带凭据的“全量账号快照”。
- 报告包含版本/系统/架构、检查时间与耗时、检查代码、配置状态、路径类别、最近安装探测结果、本地代理端口/运行时长/活跃数以及最多 20 条近期代理请求状态与耗时。
- 请求窗口保守限制为当前账号同步之后、最近一小时，并排除可能跨登录边界的请求。会话导入行、直接绕过本地代理的流量不作为调用证据。数据不足时明确说明，不能据此归责于上游或用户。
- 安装探测只复用最近五分钟的本机观察；缺失时标记缺失并提示重新检测，不为导出额外启动 CLI。配置路径不输出原文，不探测 UNC 网络路径。
- 自定义模型别名、可疑模型字符串和包含当前账号名称的模型标识隐藏；原始请求 ID 不输出。可识别的标准模型 ID 保留，方便排查。
- 网络体检最多等待 25 秒，失败可保留本机元数据；代理状态最多等待 3 秒。内存中只保留一份快照，导出/复制时校验快照 ID、会话指纹和 15 分钟有效期。
- 报告不自动上传。选择导出文件时才写用户选择的位置；复制/导出不重新体检。

## 对抗性检查

| 反例 | 防护/回归 |
| --- | --- |
| 两页同时首次检测 | 共享 Query 和进行中请求，只发起一次本机检测 |
| 不同工具、WSL 参数或新路径同时检测 | 独立键，不能混用结果；全局并发最多 3 |
| 已安装新版本但上次结果仍在途 | 检测代次变更；旧结果不写入快照 |
| 缓存过期/损坏/来自未来/包含意外字段 | 校验、限长；只持久化已知字段，不保存原始 stderr |
| 本机检测失败 | 保留展示快照并提示；不假装未安装，也不替代启动验证 |
| A 切换 B 或重新登录 | 查询隔离；旧快照无法通过后端会话指纹校验 |
| Copy/Export 再执行一次体检 | 改为读取同一份快照，测试验证不触发 refetch |
| Token、姓名、私人目录嵌在错误/分组中 | 不输出原始消息、分组名称或路径；只保留白名单字段 |
| 旧失败后已有成功 | 仅以每个工具最新记录判断，旧失败不会持续报警 |
| HTTP 200 但存在流式错误 | 保留 errorPresent 布尔值，不误判成功、不导出错误正文 |
| 超时后无可修复项目 | 只提供重新检查，不自动重建凭据 |
| 查询请求记录触发费用回填 | 使用只读窄查询，测试验证 total_changes 不变 |
