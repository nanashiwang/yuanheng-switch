# 令牌分组恢复：第一性原理与对抗性审查

## 范围与根因

本次只修复客户端分组恢复与提交行为，不改变服务端渠道、报价、账户权限、
模型映射或官方登录配置。

工具管理此前将模型/推理等级回填到组件状态，却没有恢复工具状态中的 group。
第二个 effect 因此按默认策略选组，启动和批量配置会将这个 UI 默认值写回。
另一个问题是 CompactSelectPicker 对不在选项中的非空值显示第一项。

## 不变量

- 草稿是用户本次编辑，不应与远程保存值或推荐值混存。
- 当前用户草稿优先，其次该工具的保存值；只有新工具可以推荐默认组。
- 未取得工具状态前不初始化推荐配置；切换账号或连接时清除页面草稿。
- 模型/分组暂时不在目录中不等于权限撤销；保留原值，在真正提交时预检。
- 仅刷新或打开页面不能更改实际配置；原分组缺失时也不能静默选择第一项。
- 预检、配置共享同次点击的参数快照；预检失败不能进入写入/启动。
- 预检期间锁定重复提交与选择器，离开页面或切换账号后不继续写入或启动。
- Codex 模型立即切换保持现有体验，但跨组切换需要用户确认。

## 验证

新增 14 个组件/策略用例，覆盖：

1. 独立恢复 Claude/Codex/Gemini 分组，直接启动无额外写入。
2. 账号目录与工具状态两种到达顺序，重挂载恢复。
3. 外部刷新更新未编辑工具，不覆盖本地草稿。
4. 模型切换保留原组，预检和保存收到相同参数。
5. 分组目录缺失/不完整，失败预检不修改配置。
6. 显式配置保存后重开、批量配置分别保留原组。
7. 重复点击、预检期间选择器禁用。
8. 切换账号清除草稿，并取消旧预检的后续写操作。
9. 缺失非空值的下拉框不伪装成首项。
10. Codex 跨组切换确认和取消两个分支。

全量测试 128 文件 / 808 用例通过，类型检查通过。成功配置的旧集成
测试补齐了真实流程所需的分组目录；缺失目录路径由新增失败用例单独覆盖。

## 边界

- 不自动修复旧版本已错误保存的组，因为无法推断用户原本意图。
- 工具管理里仅修改下拉框是草稿，需点击配置或启动才持久化。
- 取消发生在预检与后续调用的边界，已发到后端的写请求不能在前端撤销。
- 测试使用模拟账号与接口，未读写真实用户凭据或运行收费模型请求。
- Windows/macOS 实机反馈仍需发布后复测；通过 CI 不等于已验证用户设备。
