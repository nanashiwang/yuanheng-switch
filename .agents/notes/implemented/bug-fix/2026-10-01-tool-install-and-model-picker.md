# Agent Note: 安装生命周期反馈与模型选择连续性

Status: implemented

## Problem

首次安装必须区分缺少运行时、下载执行中、可运行验证成功。工具页和快捷控制台直接 await 静默 CLI 命令，按钮状态仅覆盖桌面应用监测，不能防止重复点击，也把进程退出成功当作可用。Windows Claude 安装走 npm，缺少 Node 的环境失败。模型选择器打开后同步连接，工具状态 queryKey 含 lastSyncedAt，时间戳变化使状态暂时消失，快捷控制台切换 loading、工具页 supported 条件失效，卸载正在滚动的选择器。

## Decision

- 复用工具安装 IPC 和已有版本探测；共享 CLI 安装状态，立即显示执行/验证阶段，失败释放锁，验证可运行后才报成功。后端对重叠工具请求加互斥，防止跨入口重复执行。
- Windows Claude 使用官方原生安装器，不要求 npm。其他 npm 安装在相同执行环境中检查 node/npm；缺失返回可行动提示和官方下载入口，不静默变更全局运行时。
- 工具状态缓存只按服务地址、账号与连接状态隔离；同账号刷新失效重取但保留已知数据，不用同步时间充当身份。模型弹层正常保留选择、Esc 与外部点击关闭，不阻断滚动事件掩盖卸载。
- 受影响入口：快捷控制台/焦点卡、工具页、关于页、安装后本机检测；不变更配置写入和平台凭据。
- Windows 每个安装任务使用独立 UUID 临时批处理路径；同 PID 下不同工具可并行，不再覆盖或删除彼此的脚本。脚本完成或启动失败后沿用原清理流程。

## Alternatives considered

- 为所有新用户自动全局安装 Node：一键程度更高，但会改变用户包管理与 PATH、引入权限和版本冲突；原生 CLI 不应强依赖 Node，npm-only 工具提供明确先决条件与用户主动安装入口。
- 禁止弹层任何关闭或延迟刷新：容易表面解决，但掩盖组件卸载、破坏 Esc/外部点击或模型新鲜度；修复缓存身份而不是吞交互事件。
- 各页面各自增加 loading：代码更少，但切换页面与多入口会重复执行；共享生命周期与后端互斥守住实际任务唯一性。

## Verification

- 原代码运行 `ModelPicker.refresh.test.tsx` 回归失败：弹层被 loading 替换；修复后刷新成功/失败、80 项列表滚动、底部选项和 Esc 回归通过。
- 独立 Chrome 无用户配置的浏览器测试：连续 12 次真实滚轮，确认 scrollTop 增长且弹层保持展开；选择 model-79、Esc、外部点击均正常；后台刷新失败仍保持展开。安装立即禁用按钮，重复点击只执行一次，验证完成后才成功。模拟 Tauri IPC，不执行实际安装。
- 前端全量 825 项测试、TypeScript、renderer 构建、格式、版本和笔记校验通过。账号、地址、退出登录三种边界不沿用旧工具数据。
- Rust 回归覆盖锁的原子性/失败释放、POSIX/Windows 无 Node 环境先拒绝 npm、Windows 原生 Claude 命令、WSL 平台语义；三平台 CI 的格式、Clippy 和测试是合并门禁。不同 Windows 工具的临时路径另有互不覆盖回归。
- 本轮浏览器、Vite、测试命令结束后检查遗留进程为零；没有实际全局安装、收费模型请求或系统配置变更。

## Consequences

同账号后台刷新不再中断选择，账号隔离仍由稳定身份字段保障；更新内容依赖现有刷新失效通知与定期查询，不把同步时间当成全新账号。失效后的真实权限/支持状态变化仍可影响可选项。

依赖安装官方网络可达性；干净 Windows 真机交互不由源码或模拟测试替代。npm-only 工具仍需用户主动准备 Node.js LTS 并重启客户端，WSL 依赖必须装在发行版内。下载字节进度不可由静默第三方安装器可靠推导，不显示虚假百分比。原生安装的超时和真实取消由 [后续安装监督](2026-10-01-bounded-tool-installation.md) 补齐；WSL、升级与只读版本验证仍不假冒取消能力。状态持续到真实进程和验证结束。发布仍沿用三平台签名构建与集中清单验证。
