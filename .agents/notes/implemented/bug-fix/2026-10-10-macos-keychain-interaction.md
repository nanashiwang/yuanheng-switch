# Agent Note: macOS 凭据读取不自动弹出钥匙串授权

Status: implemented

## Problem

更新后启动客户端会读取登录凭据。旧包采用随二进制改变的 ad-hoc 签名，无法提供跨更新的稳定代码身份；钥匙串可能要求重新授权。现有启动迁移、连接状态和订阅刷新均允许系统交互，用户未操作时就可能被弹窗打断。当前运行的本地 v0.1.65 确认为 ad-hoc 签名；用户尚未提供弹窗中的具体条目，不能将两类读取路径中的某一类认定为唯一现场原因。

## Existing capabilities and impact

复用 [系统凭据封装](../../../../src-tauri/src/secure_storage.rs)、[元衡连接状态/登录迁移](../../../../src-tauri/src/commands/yuanheng.rs)、[连接面板](../../../../src/components/desktop/YuanhengConnectionPanel.tsx)；保留凭据库保护和 SQLite 先写回读再删除的迁移顺序。已搜索活跃笔记，只有[签名发布笔记](../process/2026-10-09-macos-developer-id-release.md)部分相关：该笔记负责稳定签名，此篇补充运行期交互边界。订阅服务目前通过 security 子进程读取其他工具的凭据，需要同时移除隐式弹窗来源。

## Decision

macOS 原生凭据操作默认禁止交互，只在同步调用期间改变该进程的 Keychain Services 交互状态，串行执行并恢复原状态，不跨 await。被保护/拒绝的元衡凭据返回稳定的恢复错误；现有登录面板提供明确的“恢复本机登录”操作，仅它可以授权读取本应用的固定凭据项，不接受任意 service/account。成功读取的值仅在进程内复用，写入和删除保持缓存一致；拒绝不清空原凭据、不自动重试授权。

其他工具订阅查询使用同一无交互边界和原生 API，无法静默读取时继续现有文件回退，不授权访问第三方钥匙串。正式包继续由 Developer ID 签名、公证，旧 ad-hoc 包的首次恢复可能仍需用户主动授权；不改变 ACL 或放行其他应用。

## Alternatives considered

- **只等待签名版发布**：能建立后续版本稳定身份，但旧条目的首次迁移和被锁定钥匙串仍可能打断启动，因此需补齐运行期交互边界。
- **改回明文文件或 SQLite**：完全避开钥匙串，但降低原有会话和令牌保护，拒绝。
- **静默失败且不提供恢复入口**：改动较少，但会让已有登录用户只能看到失效表单，无法恢复受保护的旧条目，拒绝。
- **永久关闭系统交互或放宽条目 ACL**：前者影响其他凭据调用，后者降低访问保护；只在串行同步调用内临时禁用并恢复状态。

## Consequences

正常启动和后台刷新不会弹出凭据授权；无权限不清空旧值。连接查询禁用错误后的挂载重试，避免 App 加载态与登录面板之间反复切换。只有主动恢复会读取固定元衡条目，成功后进入现有工作台；拒绝后保留可再次操作的入口，授权按钮等待期间禁用。新文案覆盖现有五种语言。

旧包钥匙串 ACL 无法无授权绕过，恢复可能需对已有元衡条目一次性授权。禁用交互使第三方钥匙串中仅限原工具访问的令牌不再能用于自动额度查询，文件回退仍可用。进程内缓存只复用已授权取得的值，写入/删除先移除旧缓存；迁移校验直接读取平台存储，不以缓存代替落盘验证。Apple 公证队列可能继续阻止正式发布，不能以触发构建代替成功。

## Verification

本地完整 Rust 测试 2457 项通过、2 项既有忽略；原生独立临时钥匙串测试覆盖解锁时可读取、锁定后 legacy API 和 SecItemCopyMatching 均立即失败、交互状态恢复。缓存回归覆盖成功复用、写入/删除、失败清除旧缓存和部分恢复不发布。测试不读取用户真实凭据。

完整前端 869 项通过，包含 App 启动拒绝后只读取一次、恢复只由点击触发、取消不重试、等待禁止重复操作、恢复成功和普通错误不显示授权入口。类型、格式、Clippy、renderer 构建和版本一致性检查通过；构建仅有既有大块体积提示。实际应用壳通过本地模拟 IPC 浏览器验收：暗色/浅色、900×600 最小窗口、刷新、取消、成功回到工作台。模拟 UI 不代替用户真实旧 ACL 的手动授权验收；当前 Mac 锁屏，未操作其真实系统授权弹窗。
