# Agent Note: 账号密码重新登录不依赖旧钥匙串权限

Status: implemented

## Problem

v0.1.68 的账号密码认证成功后，persist_connection 仍覆盖固定旧凭据项；macOS setter 先读旧值，旧 ACL 拒绝时整次登录失败。两步验证的临时 Cookie 和完成登录后的旧条目清理也可能阻断登录。上一轮只覆盖了恢复入口，未覆盖旧条目被拒绝时的完整重新登录。

## Decision

复用账号密码认证、系统凭据封装和连接查询；macOS 新登录把完整会话写入独立随机标识的单个系统凭据项，回读验证后，事务更新非敏感选择器与账号缓存。新登录不读取或删除旧固定项；新选择器存在后不再回退旧凭据。系统凭据库无法保存时仅在 AppState 内保留会话，持久化不含秘密的本次运行标记并明确提示重启后重新登录。两步验证临时 Cookie 只在内存保留。退出后保留登出标记，防止下次启动重新捡回旧会话；工具配置不受影响。Windows/Linux 保持原有凭据存储路径。

活跃笔记审计：[旧交互边界](../bug-fix/2026-10-10-macos-keychain-interaction.md)部分重叠，保留并互链；[签名发布](../process/2026-10-09-macos-developer-id-release.md)只负责包身份；安装流程及模型收藏笔记无关。此项补充新认证与旧凭据恢复的边界，不改变静默后台访问和不落盘明文凭据的决定。

## Alternatives considered

- 强制先恢复旧条目：实现最少，但用户已重新提交账号密码，不应依赖另一次旧凭据授权。
- 只换固定的新 key：可避开首次旧 ACL，但多字段写入可能留下混合账号，下一次存储失败仍阻断登录。
- 整体明文落盘或放宽 ACL：降低既有保护，拒绝；内存会话不持久化秘密。
- 每次登录都仅内存保存：完全不访问钥匙串，但所有用户每次启动都需登录；只在系统存储不可用时使用该模式。

## Consequences

登录失败或尚未完成两步验证时的客户端升级入口由[免登录更新](2026-10-10-update-without-login.md)负责，复用原有全局更新器，不依赖此处的会话恢复。

旧固定系统凭据项继续受原 ACL 保护，新登录不会读写它们；过期的新会话项仅在新账号状态提交后尝试无交互清理，失败不影响登录。会话写入及原生回读验证失败时，仅发布本次运行标记和公开账号缓存，所有秘密留在 AppState；重启明确处于未登录状态。凭据选择器、账号缓存和旧 SQLite 凭据清理在同一事务提交，失败不会发布部分账号。完整账号状态读取与会话切换串行，旧账号公开资料不得与新会话混合。恢复仅接受内部生成的 UUID 标识，不能指定其他服务。

账号密码和验证码仍按原平台认证流程验证；更改的是成功认证后的本地会话保存，不绕过远端认证。新会话的退出会保留登出标记、清除当前会话，不修改既有工具配置。无法删除的旧钥匙串项可能继续存在，但不会自动回退读取。系统存储不可用时关闭后需要重新登录，界面在登录成功通知与连接页明确说明。密码不会保存到本机。

## Verification

本地完整 Rust 测试 2463 项通过、2 项既有忽略，Clippy 通过。新增 5 项后端回归验证：旧固定项全部拒绝时新登录仍持久化成功并可重启；全存储拒绝时两步验证、登录和刷新仅内存可用；退出或重启不回退旧账号；回读失败不声称记住登录；SQLite 失败保留原账号与选择器；缺失新项及非法选择器不读取任意旧项。故障注入仅位于 test cfg，使用虚构会话，不读取用户真实凭据。

完整前端 873 项通过；最终连接面板与 App 集成 38 项通过，覆盖账号密码直接登录、仅内存提示、旧项拒绝后的两步验证、恢复取消和旧登录表单不循环读取。真实应用壳通过本地模拟 IPC 浏览器验收：深浅色、900×600、普通登录与两步验证均可进入已登录界面，模拟恢复次数为 0；进入两步验证后不再显示旧登录恢复入口。类型、renderer 构建和版本检查通过，构建仅有既有大块体积提示。模拟 UI 不代替真实用户账号认证，系统库故障用隔离测试替身覆盖。

版本为 v0.1.69，公告保留上一公开版 v0.1.68。三平台 CI、Apple 公证、Release 安装包和镜像以实际发布流程结果验收，不以触发构建代替成功。
