# Agent Note: Claude Windows 网关故障可观测性与安装识别

Status: implemented

## Problem

Claude Desktop 在 Windows 上出现连接空响应；本机健康与认证检查正常，不足以证明有效请求转发成功。Core 分离进程没有可靠落盘的故障阶段记录，体检却将进程存活描述为桌面可用。已确认的 Claude MSIX 包族不满足现有 Anthropic 前缀规则，会漏检。本地全新子进程测试进一步复现了 TLS 后端缺失引起的连接器 panic；该缺陷高度符合用户现象，但用户 Windows 的完整链路仍待验证。

## Existing capabilities and impact

复用 `YuanhengHealthCard` 的检查详情、预览、复制和导出，同一快照维持当前账号边界。扩展 `core_daemon`、本地路由和 `support_diagnostics`，不另建日志上传服务。调整 `desktop_app_detection` 的已知包身份识别。

检索活跃笔记中的 Claude/Core/日志/诊断/Windows，无相关 owner note；已有流程笔记不涉及运行行为，不修改。

## Decision

- 两条 TLS 连接器在使用点显式选择 ring，不依赖 GUI 或进程默认 provider；保留原始连接器的 Mozilla/系统信任根、fallback 的 Mozilla 根和主机名验证。原实现的全新子进程测试两处均 panic，修改后通过，且进程默认 provider 仍为空。
- 在 Core 记录有容量上限的结构化阶段事件，使用固定枚举，不持久化原始请求、响应、错误消息、路径、令牌或模型名称。异常和连接取消不能伪装为已完成请求。
- Claude messages 的异步处理 panic 返回安全 HTTP 500；记录阶段但不重试、不宣称修复根因。流式响应须区别响应头返回和响应体结束。
- 体检展示实际 Core 版本、诊断能力和最近阶段记录；账号切换后的报告不包含切换前开始的请求。修正存活检查文案，区分配置、认证和实际推理。schemaVersion 为 3，旧 Core 的可选诊断字段缺失会明确提示，不改 Core 管理协议版本。
- 增加不触发模型调用的本地认证/配置检查；不自动发送收费请求，不修改系统虚拟化、防火墙、回环豁免或代理。
- 兼容已确认的 Claude MSIX 包族，拒绝相似名称和错误发布者。Windows 环境未验证时明确标注，不能显示全流程正常。

## Alternatives considered

- 将 GUI 的全局 crypto 初始化复制到 Core 改动最小，但仍依赖调用顺序，测试和其它独立入口可能再次遗漏；连接器显式选择后端能在使用点守住约束。不能以关闭 TLS 证书验证代替修复。
- 原始 stderr 全量落盘最利于观察，但现有日志会带用户路径、供应商别名甚至错误正文，自动分享风险大；选固定字段的阶段日志，保留前台原始诊断作为人工操作。
- 只改提示与恢复脚本风险小，但仍需用户人工停止服务才能定位；复用既有诊断导出入口更能减少反复试错。
- 直接放宽到任意 Claude 包名可减少漏检，但扩大信任边界；只增加确认的包身份，不修改其它 Agent 规则。
- 通过真实模型调用证明可用最直接，但会产生费用或重复请求；默认仅做不收费的本地探测，真实推理留给明确授权的 Windows 验收。

## Verification

- Rust 完整测试：2434 通过，2 项原有忽略；Clippy `-D warnings`、格式检查通过。前端类型检查、816 项测试和 renderer 构建通过。
- 新测试覆盖无 GUI 初始化的两个 TLS 连接器、401/解析/模型路由错误的 HTTP 返回、handler 和 body panic、响应帧/尾部保留、未消费 body 取消、并发阶段隔离、日志轮转/容量/写盘失败、导出账号时间边界与隐私。
- 无费用的模型目录探测覆盖 200/401/302/异常 JSON/空目录，拒绝外部 URL、用户信息和管理端点，不跟随重定向。虚拟化查询覆盖启用、关闭、未知与异常输出。
- 新包身份接受、错误发布者/空 AppID/路径注入拒绝；真实 Windows 包注册和 CIM 分支尚未实机执行。
- 验收步骤见 [Windows 本地验收](../../../../docs/reviews/2026-10-01-claude-windows-diagnostics.md)。未进行实际模型推理，未生成 Windows 安装包，也未推送或发布。

## Consequences

使用点选择后端修复独立 Core 与 GUI 生命周期耦合；结构化记录减少手动重启抓取原始日志的需求，但不能提供任意错误正文或堆栈。保留 128 条内存阶段事件、256 KiB 单文件及一份轮转文件；报告最多输出 40 条，原请求 ID 仅本地保存，导出按本次快照生成别名。初版同步写盘取舍及旧包前缀兼容由 [后续审查加固](2026-10-01-diagnostics-review-hardening.md) 替代；请求现使用有界后台队列，慢盘可能丢弃持久化记录并显式计数，不再让请求线程等待磁盘。

panic 恢复无法覆盖进程退出、HTTP 解析前断线或 native 崩溃。观察 HTTP 响应完成不代表模型正确回答或计费成功；客户端仍可能依据自身策略重试。MSIX 注册/下载/安全策略仍需用户 Windows 验证。诊断不自动修复未知配置，不改变计费或模型选择；本轮仅本地修改，暂不发布。
