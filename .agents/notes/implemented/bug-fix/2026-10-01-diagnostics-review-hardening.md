# Agent Note: 诊断后台写入与 Claude 包身份收紧

Status: implemented

## Problem

请求阶段日志在请求线程同步写盘并持有内存日志锁，慢盘会拖慢请求与健康检查。旧 Claude MSIX 分支使用 Anthropic 前缀和 Claude 子串判断身份，尚未得到确认的包族也可能通过。

## Existing capabilities and impact

复用 `core_diagnostics` 的固定枚举、128 条内存记录、轮转和账号边界，以及智能体检快照；不新增原始日志上传或外部服务。`desktop_app_detection` 已识别一个确认的 Claude 包族；本轮收紧自动候选筛选与最终 AUMID 校验，不改其它 Agent 规则。

活跃笔记检索：与 [上一轮诊断修复](2026-10-01-claude-windows-diagnostics.md) 部分重叠。保留其 TLS、请求异常保护和体检设计；本决策替代同步日志写盘取舍，并删除未验证的旧包前缀信任。流程笔记无关。

## Decision

- 使用一个独立写入线程和 128 条容量的队列，请求用 `try_send`，磁盘操作不持有内存快照锁。另有至多一条进行中的写入。队列满、写入失败、线程停止均计数，不假装日志完整，不影响模型请求。
- 正常 Core 退出时最多等待两秒排空日志；不因坏磁盘无限等候。测试中的写入线程释放并回收；异常进程退出仍可能丢失尚未落盘的队列记录。
- 仅接受确认的 Claude 完整包族；AppID 仍要求合法格式。PowerShell 候选先过滤同一允许列表，避免伪造候选排序靠前导致合法包漏检；不动 WindowsApps 权限。
- 诊断导出展示队列/丢弃/写入错误计数和写入线程状态；不导出原始错误或新增个人信息。

## Alternatives considered

- 同步小日志实现最简单且落盘及时，但慢盘可阻塞正常推理；不再接受该请求链路风险。
- 每个事件 `spawn_blocking` 不阻塞 async worker，但任务数无界、顺序及轮转锁更难控制；改用唯一消费者的有界队列。
- 继续信任 Anthropic 前缀可兼容未知旧包，但名称不是可信身份依据；只放行已确认完整包族。未来补充旧包须提供签名和发布者身份验证证据，不猜测 publisher ID。

## Verification

- 新增阻塞写入模拟：消费第一条时人为阻塞，容量 2 的队列只接收两条等待记录，多余记录立即计数丢弃；HTTP 响应和内存快照继续完成，退出等待按期限返回，释放模拟磁盘后回收线程。
- 覆盖正常退出排空所有已接受记录、消费者 panic、退出后的入队、写入失败后继续写入及已有轮转/并发/隐私测试。
- 确认的 Claude 包族接受；Anthropic 假前缀、错误后缀、空/注入 AppID 拒绝，Codex 原规则不改变。Windows 实际注册/启动由用户验证。
- Rust 完整回归 2438 通过、2 项原有忽略；前端 816 项通过、类型检查通过，Clippy `-D warnings`、格式和决策笔记校验通过。

## Consequences

极慢盘可能使后台线程停在操作系统调用；无法安全中断文件写入，只限制队列和退出等待。采用内存记录优先且明确显示丢弃，比让请求无限等待更合适。只接受已知包族可能影响未知旧版 MSIX 的自动识别；不删除安装和配置，待身份验证后再扩展。

计数是本机 Core 生命周期范围的诊断状态，不是账号的请求或计费统计。队列暂存和进程强制退出可能导致最近记录尚未落盘；预览/复制/导出使用内存快照时不会等待磁盘。没有自动恢复线程或重发请求机制，线程异常后需在无请求时重启 Core。本轮未推送或发布安装包。
